# تشغيل نظام عقود السيارات مع Firebase (GitHub Pages)

## الميزات
- التصميم الأصلي ونموذج الطباعة في `index.html` و`styles.css` محفوظان؛ أُضيف ملف JavaScript واحد للنظام.
- تسجيل دخول بالإيميل وكلمة المرور (لا توجد صفحة تسجيل مستخدم عام).
- توليد رقم عقد من 1001 عبر **Firestore transaction**، تزامني وآمن ضد تنازع الرقم بين أجهزة متعددة.
- حفظ العقد كاملاً، استدعاؤه برقمه، عرض أحدث 20 عقداً، والتعديل بنفس الرقم.
- منع الطباعة قبل حفظ العقد أو وجود تعديلات غير محفوظة.
- حماية بيانات العقود بقواعد Firestore؛ لا يمكن قراءة السجلات دون حساب Firebase Authentication مفعل.

## خطوات الإعداد
1. أنشئ مشروعاً في https://console.firebase.google.com/ ، ثم أضف Web App.
2. من **Authentication > Sign-in method** فعّل **Email/Password**، ثم من **Users** أنشئ حساب المستخدم/الموظف يدوياً. تجنّب فتح تسجيل عام.
3. من **Firestore Database** أنشئ قاعدة البيانات في المنطقة المناسبة. يمكن الاختيار بين الوضع المقفل ثم لصق القواعد أدناه. لا تستخدم قواعد `allow read, write: if true`.
4. افتح **Firestore Database > Rules** واستبدل القواعد بالكامل بنص ملف `firestore.rules` ثم انشرها.
5. انسخ كائن `firebaseConfig` من **Project settings > Your apps > SDK setup and configuration (Config)** والصقه في `js/firebase-config.js`، بدلاً من قيم PASTE. هذه المفاتيح تعريفية للعميل وليست بيانات اعتماد إدارية.
6. في **Authentication > Settings > Authorized domains** أضف نطاق GitHub Pages الخاص بك مثل `yourname.github.io` إن لم يكن مسجلاً. لا تضع `https://` أو مسار المستودع.
7. ارفع الملفات المعدلة نفسها إلى مستودع GitHub Pages، وافتح الرابط. سجّل الدخول، املأ اسمي البائع والمشتري، واضغط **حفظ العقد** ليصدر العقد 1001، ثم أجرِ عقداً آخر للتأكد من ظهور 1002.

## ملاحظات مهمة
- رقم العقد **لا يُخصص نهائياً إلا بعد نجاح الحفظ** في Firestore؛ هذا يمنع أرقاماً مكررة أو محجوزة لمجرد فتح الصفحة.
- العداد في `metadata/contractCounter` لا يُعدل يدوياً. لا تحذف العقود أو العداد من لوحة Firebase دون خطة ترحيل.
- المتاح بالتصميم الحالي أن كل حساب أنشأته في Firebase Authentication يستطيع قراءة وتعديل جميع العقود؛ إذا أردت صلاحيات منفصلة للموظفين فلابد من إضافة قواعد أدوار (roles) لاحقاً.
- بيانات العملاء الشخصية حساسة: امنح حسابات Firebase فقط للموظفين المخولين، فعّل MFA على حساب Google المسؤول، وطبّق النسخ الاحتياطي وضوابط الوصول. لا ترفع بيانات الحسابات أو مفاتيح Service Account إلى GitHub.
- قواعد Firestore تؤمن **البيانات** لا شفرة HTML/CSS المنشورة علناً على GitHub Pages؛ الواجهة لا تظهر العقود لمن لم يسجل دخوله، لكن ملفات الويب نفسها عامة بطبيعة الاستضافة.
- كل قراءة/كتابة لها حدود وفق باقة Spark الحالية، تحقق من صفحة Firebase Pricing. لا يلزم خادم مدفوع لهذا التنفيذ.
- تخضع رسائل الأخطاء للمتصفح / إعداد المشروع، ولا يمكن اختبار الاتصال الفعلي دون مفاتيحك ومشروعك.

## الملفات
- `index.html`: فقط سطر استدعاء الموديول في الأسفل أضيف.
- `styles.css` و `script.js`: بلا تعديل.
- `js/firebase-config.js`: إعداد مشروعك.
- `js/firebase-contracts.js`: المنطق الخاص بالمصادقة والعقود.
- `firestore.rules`: قواعد أمان قاعدة البيانات، تنشر في Firebase Console ولا تعمل بمجرد رفع الملف إلى GitHub.
